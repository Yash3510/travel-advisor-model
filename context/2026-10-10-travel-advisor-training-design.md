# Travel advisor: Qwen3.5-0.8B fine-tune (design + plan)

Date: 2026-10-10 · Status: approved in chat ("go with whatever you think is best")

## Goal

Fine-tune Qwen3.5-0.8B into the AI travel advisor described in the friend's behaviour spec
("AI Travel Sales Agent — Behavioral & Training Specification", v1.0).
The result is a GGUF in the Bionic models folder that runs CPU-only and passes the spec's release gates.

## Constraints

- **Cost:** zero. Training runs on the RTX 4050 (6 GB); inference runs on the i7-13650HX CPU (best at 8 threads).
- **Data sources:** open datasets first. Generate only what they lack.
- **Teacher:** Qwen3.5-4B Q6_K (Apache-2.0), run locally on GPU. Claude does not write training text (consumer terms §3); Claude designs scenarios, writes checks, reviews samples and scores.
- **Training:** Studio's Python env (unsloth 2026.10.2, TRL 0.23.1, transformers 5.5.0). The data pipeline lives in this uv project.

## Baseline (base 0.8B, spec §15 prompt, 30 scenarios from spec §17)

- 7 critical failures, average 0.8/4. Main failure: reflex tool calls with invented arguments.
- CPU speed: 20.6 tok/s generation and ~110 tok/s prompt reading at 8 threads.

## Data

| Part | Source | How | Teaches |
|---|---|---|---|
| Core (~70%) | Schema-Guided Dialogue (CC-BY-SA-4.0): Flights, Hotels, Buses, Trains, RentalCars, Travel | Script conversion of annotated `service_call` / `service_results` into tool calls. Dates 2019→2027, $→₹. | Ask for missing info, exact tool args, confirm before reserve, success only after the API, failure notices |
| Gaps (~30%) | Generated by the 4B teacher against a deterministic mock travel backend | Hard-case seeds for the spec §14.1 categories that SGD lacks | Safety/emergency, accessibility, health, visa without passport, fictional places, refund pressure, competitor, PII, infeasible plans, tool errors, pending/failed bookings, non-refundable disclosure, stop-selling, human handoff |

**Leakage guard:** the 30 eval scenarios are never used to seed training. Hard-case seeds use different places, numbers and wording (for example, no Andaman-by-train), and a similarity check rejects near-copies.

**Automatic checks** drop any conversation that has:
- an invalid or unoffered tool call, or missing required arguments
- `create_booking` without a prior summary plus an explicit user confirmation
- status words that contradict the tool result
- ₹ amounts absent from the conversation
- an emergency reply without "112"
- more than 2 questions in a discovery turn

Claude then spot-checks a sample by hand.

## Training

- **Model:** `unsloth/Qwen3.5-0.8B` (text only), LoRA r = 32, bf16.
- **Format:** chat `messages` + `tools`, loss on assistant turns only.
- **Prompt:** short runtime system prompt (~100 tokens).
- **Export:** merge → GGUF Q8_0 → `.lmstudio/models/local/travel-advisor-qwen3.5-0.8b/`.

## Done when

On the same 30 scenarios (short runtime prompt, CPU, 8 threads), the fine-tuned model has **0 critical failures** and **averages ≥ 3/4**, scored by Claude with the spec §16 rubric. If it falls short, report honestly what is left.

## Plan

1. Scaffold the project; move the eval harness in, sharing one source of tool schemas.
2. Teacher check: run the 4B on the 30 scenarios on GPU, with and without thinking. It must clearly beat the student, or stop and reassess.
3. SGD: download the travel files, convert them, and test the converter (TDD).
4. Mock backend + hard-case seeds + simulator (teacher agent + teacher user-sim) + validators (TDD).
5. Generate the gap data, validate it, and spot-check.
6. Build the training JSONL; train the LoRA on GPU; export the GGUF to the Bionic folder.
7. Eval on CPU, score, and report.
